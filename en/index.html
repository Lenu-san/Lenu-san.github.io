Methods and tools

How I run an audit or troubleshooting assignment, and with what.

Firewall audit approach

  1. 1
    Collection

    Retrieval of the configuration export (Forcepoint SMC, FortiOS backup, pfSense) following a documented collection procedure.

  2. 2
    Flattening

    Rebuilding the rule table: objects, groups, VDOMs, sub-policies, interfaces.

  3. 3
    Qualification

    Spotting permissive, obsolete, disabled, unlogged or undocumented rules; checking the logging setup.

  4. 4
    Analysis

    Exposure of sensitive services, clear-text protocols, wide ranges, associated risks and business context.

  5. 5
    Reporting

    Audit report with rationalisation and hardening recommendations, presented to the CISO.

Auditing tool

fw-audit

Security objective
Automatically spot classic misconfigurations in a firewall rule set.
Problem addressed
Reading several hundred rules by hand is slow and error-prone. The tool applies five checks — “any → any” rule, sensitive service exposed to any source (exact port or a range containing it), clear-text protocol, wide port range, undocumented rule — with a severity and a recommendation for each finding.
Environment and tools
  • Python 3
  • Standard library
  • CSV
  • Command line
Results
18 passing unit tests. Also reads the fortigate-policy-parser CSV export directly (disabled policies skipped, FortiOS services translated into ports, findings tied to the policy id). Validated on a 9-rule sample set and 5 FortiGate policies.
Skills applied
Firewall rule analysis, risk qualification, recommendations.

Infrastructure auditing · high availability

haproxy-audit

Security objective
Review an HAProxy configuration with an auditor's eye: exposure, TLS, logging, hardening, and the ability to survive an outage.
Problem addressed
An unauthenticated stats page, an enabled stats admin, TLS 1.0 still accepted or a node without a health check stay invisible until an incident. The tool splits haproxy.cfg into sections, applies defaults inheritance and reports 20 security and high-availability checks with a severity and a recommendation.
Environment and tools
  • Python 3
  • Standard library
  • HAProxy
  • Keepalived / VRRP
Results
13 passing unit tests; on the sample configuration: 1 critical, 3 high and 6 medium findings; the hardened version reports nothing. Static analysis of a single file, ACLs not interpreted.
Skills applied
Infrastructure security, high availability, configuration analysis, recommendations.

Web filtering and high availability

pac-check

Security objective
Validate a PAC file before rollout, like any other configuration.
Problem addressed
A badly written exclusion or a misordered failover chain breaks an access path or high availability, and you only notice once the file is deployed. The tool evaluates FindProxyForURL outside the browser and compares the result with an expectations file.
Environment and tools
  • Node.js 18+
  • Zero dependencies
  • vm sandbox
  • PAC / proxy
Results
6/6 expectations verified on the sample PAC; 7 passing automated tests (node:test). Does not reproduce the https URL truncation performed by browsers.
Skills applied
Web filtering, high availability, proxy operations.

Operational security

log-secret-scanner

Security objective
Detect clear-text secrets in logs and configuration files, without ever displaying them.
Problem addressed
A service that logs a password or an Authorization header exposes that secret to anyone reading the logs and to the collection platform. Ten patterns, one severity per pattern, already-masked values ignored, .gz archives read as a stream.
Environment and tools
  • Python 3
  • Standard library
  • Regular expressions
  • .gz archives
Results
11 passing unit tests; 6 redacted findings on the sample log. Pattern-based detection only, no entropy analysis.
Skills applied
Operational security, log management, reporting and remediation.

Credential hygiene

pwned-check

Security objective
Check whether a password is compromised without ever exposing it.
Problem addressed
Have I Been Pwned's k-anonymity model reimplemented: local SHA-1 hashing, only the first five characters of the digest are sent, final comparison happens locally, response padded through the Add-Padding header.
Environment and tools
  • Node.js 18+
  • Zero dependencies
  • HIBP API
  • SHA-1 / k-anonymity
Results
Hidden input and distinct exit codes (not found, compromised, error). One password at a time; no automated tests.
Skills applied
Credential hygiene, security awareness.
